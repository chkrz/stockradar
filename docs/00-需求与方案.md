## 一、结论先行

做一个**美股为主(兼顾 A 股/港股)的基本面投资"信息雷达"**。
第一步不做交易、不做选股模型,只解决一件事:**把 Twitter 上一批股票意见领袖(KOL)的推文,自动抓取、结构化落库,并用一个简单网页浏览筛选**,从而 figure out "大家都在关注什么"。

技术路线已确认:
- **抓取方式**:自建爬虫(twscrape 方案为主)
- **落地形态**:数据库 + 简单网页
- **大神名单**:由我(Claude)协助一起调研补充

一句话价值:先把"别人在看什么"变成一份**可检索、可回溯、可统计**的数据资产,后续的基本面分析、热度追踪、投资决策都建在它之上。

---

## 二、目标与范围

### MVP 目标(第一阶段要交付的)
1. 维护一份 KOL 账号名单(可增删)。
2. 定时抓取这些账号的推文(含转推/回复可选),去重入库。
3. 一个简单网页:按账号、时间、关键词(股票代码/公司名)浏览和筛选推文。
4. 基础统计:近 N 天哪些 ticker / 话题被提及最多。

### 明确不在第一阶段做的(避免范围蔓延)
- 不做自动交易 / 下单。
- 不做情绪打分、AI 荐股、回测(留到二期)。
- 不做多平台(先只 Twitter,不碰 Reddit/StockTwits/雪球)。
- 不做用户系统/多租户(自用单机即可)。

## 三、已确认的关键决策

| 决策点 | 选择 | 说明 |
|---|---|---|
| 抓取方式 | 自建爬虫(twscrape) | 成本近零,但有封号与维护风险(见风险章节) |
| 落地形态 | 数据库 + 简单网页 | MVP 用 SQLite,网页用轻量方案 |

| 市场重点 | 美股为主 | ticker 识别先做美股($AAPL 等) |

## 四、技术方案(建议,待确认)

- **语言**:Python 3.11+
- **抓取**:[twscrape](https://github.com/vladkens/twscrape) — 用真实账号 cookie 登录,支持多账号轮换、限速。
- **存储**:SQLite(MVP)→ 数据量大或要并发时再迁 Postgres。
- **后端/网页**:FastAPI + 一个极简前端(先用服务端渲染的 HTML 表格,不上前端框架)。
- **调度**:先用 cron / 手动脚本;稳定后再考虑常驻定时任务。

目录结构(初步):
```
stockradar/
  docs/              # 文档(本目录)
  stockradar/        # 源码包
    scraper/         # twscrape 抓取逻辑
    db/              # 模型与入库
    web/             # FastAPI + 页面
    tickers/         # 股票代码/公司名识别
  data/              # SQLite 库、账号 cookie(不入 git)
  scripts/           # 抓取/初始化脚本
  accounts.txt       # KOL 名单(可版本化)
```

## 五、数据模型(初稿)

- **kol**:id, handle, 显示名, 分类(宏观/个股/期权/短线…), 备注, 是否启用
- **tweet**:id(平台原始 id), kol_id, 正文, 发布时间, 转推/回复标记, 点赞/转发/回复数, 抓取时间, 原文 url
- **mention**:tweet_id, ticker(如 AAPL), 匹配方式($符号 / 公司名), 用于统计热度

## 七、风险与缓解(重点)

自建爬虫是本项目最大的不确定性,必须正视:

1. **账号封禁**:X 对抓取行为敏感,登录账号可能被限流/封号。
   - 缓解:用专门的"小号"而非主号;多账号轮换;严格限速;cookie 定期维护。
2. **反爬策略变化**:X 接口/风控随时变,twscrape 可能阶段性失效。
   - 缓解:抓取层做成可替换接口,保留将来切换到第三方付费服务(Apify / TwitterAPI.io)的能力,不把逻辑写死。
3. **合规与 ToS**:抓取违反 X 服务条款,数据仅供个人研究使用,不对外分发。
4. **数据质量**:KOL 会删推/改口,需保留抓取快照与时间戳,便于回溯。
